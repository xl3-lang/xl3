# xl3 会保留什么,不会保留什么

xl3 是否适合你的模板,最终归结为一个问题:**工作簿能原样出来吗?**
这一页按功能逐项回答。

下面的内容都是规范层面的决定,而不是某个实现的偶然行为。标为*推迟*的项是有意
推迟的,并且有 ADR 记录了这件事 —— 这和「没人检查过」不是一回事。

## 四种判定

| 判定 | 含义 |
|---|---|
| **保留** | 输出与模板完全一致。任何符合规范的实现都必须做到。 |
| **保留并扩展** | 规则会保留下来，完全位于 `@repeat` 块内的范围会随输出行一起扩展。部分重叠的范围保持原样，引擎不会猜测作者在块外的意图。 |
| **保留,但范围不扩展** | 功能本身会留下来,但范围仍是模板给它的那些坐标。即使 `@repeat` 把工作表从 1 行扩到 50 行,范围也只覆盖那 1 行。每一项都有模板侧的应对办法。 |
| **推迟** | XTL 0.1 不作任何保证。它可能留下,也可能被丢弃,两个符合规范的实现给出不同结果也是允许的。1.1 之前不要依赖它。 |

## 布局与格式

| 功能 | 判定 | 说明 |
|---|---|---|
| 单元格格式 —— 字体、填充、边框、对齐 | **保留** | |
| 数字与日期格式 | **保留** | `@repeat` 扩展出的每一行都会继承,而不只是第一行 —— 见[重复块内的格式](#formatting-inside-a-repeat-block)。 |
| 行高、列宽 | **保留** | |
| 合并单元格 | **保留** | 模板里的和源数据行里的都算 (ADR-0033、ADR-0035)。 |
| 图片及其锚点 | **保留** | `@repeat` 在上方插入行时锚点**不会跟着移动**。请把图片放在页眉、页脚或侧边 —— 也就是数据块之外。 |
| 冻结窗格与拆分 | **保留** | |
| 单元格批注 | **保留** | 写在 `{{ [列] }}` 单元格上的批注会留在渲染后的单元格上。 |
| 工作表保护、单元格级锁定/隐藏标记 | **保留** | 引擎写入的单元格继承模板单元格的锁定状态,而不是合成一个默认值。 |
| 工作簿属性 —— 主题、文档属性 | **保留** | fixture `120-workbook-properties-preserved`。 |
| 静态单元格里的原生 Excel 公式 | **保留** | 不是 xl3 生成的公式会原样通过 (ADR-0046)。凡是 Excel 打开时能算的,都建议交给它 —— 见 [Cookbook 16](/guides/xtl-vs-excel-formula)。 |

## 带范围的规则

带范围的功能遵循两种契约。条件格式和数据验证仅在其原始范围完全位于 `@repeat`
块内时随输出行扩展。部分重叠保持不变，避免规则蔓延到作者有意排除的合计行。
名称定义和打印设置会保留，但坐标不变。

| 功能 | 判定 | 模板侧的应对办法 |
|---|---|---|
| 条件格式 | **保留并扩展** | 1 行块内的 `A2:A2` 在块输出 3 行时扩展为 `A2:A4`。整列范围已覆盖输出，因此保持不变；部分重叠也按原样保留。 |
| 数据验证(下拉、约束) | **保留并扩展** | 重复模板行内单元格的数据验证会复制到对应的输出行。块外的数据验证不受影响。 |
| 名称定义 | **保留,但范围不扩展** | 工作簿级和工作表级都会留下,但引用不会被重新指向扩展后的区域。 |
| 打印区域、打印标题 | **保留,但范围不扩展** | 把打印区域设为整列 (`$A:$Z`),或设为重复的标题行 (`$1:$1`)。 |

## 推迟到 1.1

有四个功能在 1.0 中被有意留作实现自定义 (ADR-0076)。下面记录参考实现当前的行为,
方便你据此规划,但**其中任何一条都不是承诺** —— 这正是「推迟」的含义。

| 功能 | 参考实现的当前行为 |
|---|---|
| 数据透视表 | 不会通过。既不能创作也不能保留。 |
| 迷你图 | 同样不会通过。 |
| 结构化表格 (ListObject) | 表格本身**会留下**,但 `ref` 不会扩展:跨着 `@repeat` 行创建的表格,之后仍只覆盖它原本覆盖的那些行。请在模板里把 `ref` 放宽到整列。 |
| 分页符 | **会丢失。** 概念上看着紧挨「打印区域」,但并不在其覆盖范围内。请在转换之后由宿主一侧设置。 |
| 图表 | 由实现自定义 (ADR-0036 第 3 项)。参考实现通过 ExcelJS 读写,而它的图表支持并不完整 —— 不要指望图表能留下来。 |

## 有意移除的部分

| 功能 | 行为 |
|---|---|
| 宏 (VBA、XLM) | **始终被剥离。** `.xlsm` 输入会被当作「已移除宏的 XLSX」接受,并发出一条警告。宏永远不会执行,在 1.x 期间宿主和模板都无法把它开回来。见 [SECURITY.md](https://github.com/xl3-lang/xl3/blob/main/SECURITY.md)。 |

## 重复块内的格式 {#formatting-inside-a-repeat-block}

范围规则和单元格级格式按不同契约扩展。完全位于重复块内的条件格式和数据验证会随
块扩展，名称定义和打印设置则不会。除此之外，所有输出行都会继承模板单元格的数字
格式和样式，而不只是第一行。

最后这项保证比听起来更重要。第 2..N 行丢掉格式属于无声的数据损失:一列里第一行显示
`1,234.50`、其余显示 `1234.5`,看起来就像一次格式失手,并且和真的失手无法区分。
带 `data-loss` 标签的九条 fixture 就是为了防止这种回归而存在的。

## 体积上限

| 上限 | 数值 |
|---|---|
| 内存 | 规模上去之后**每个输出单元格约 2.2 KB**,再加上约 130 MB 的底座。200 万单元格大致需要 4.2 GB 的峰值 RSS。 |
| 单次转换的单元格数 | 端到端验证到约 200 万;2 GB 的宿主大约能放 50 万。在假定更大的任务能跑之前,请按每单元格 2.2 KB 估算宿主规格。 |
| 单元格字符串长度 | xl3 原样写出你给的内容。Excel 在读取时会拒绝超过 32,767 个字符的单元格,而 xl3 **不做预先校验** —— 如果输出必须能在 Excel 中打开,请在传入前检查长度 (ADR-0032)。 |

超出可用内存时,表现为宿主层面的 out-of-memory,而不是一个 xl3 错误 —— xl3 无法
捕获它。耗时较长的转换支持 `AbortSignal`。

## 其中有多少是机器校验过的

一部分。而且值得知道是哪一部分。

- `123-feature-preservation` 用 Stage 1 的单元格值比较,确认名称定义和单元格批注
  能经过渲染留存下来。
- `170-data-loss-numfmt-preserved-across-expansion` 在 Stage 2 确认数字格式能越过
  `@repeat` 的展开保持住 —— 就是上面说的那个坑。
- `171-cf-dv-range-extension` 在 Stage 2 确认块内的条件格式与数据验证范围会扩展，
  而部分重叠保持不变。
- 对上面表格中*每一行*都做 Stage 2 规范化比较,仍在等 ADR-0006 的 canonicalizer
  工作。

也就是说,没有 fixture 支撑的行是规范层面的承诺,而不是机器校验过的结论。所有实现
都跑同一套[适合性语料库](/conformance),所以被校验的部分处处都被校验;但语料库还
没有覆盖这张表的全部 —— 这一页宁愿把这件事说出来,而不是让人以为不是这样。
